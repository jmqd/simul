* Audit findings (2026-10-22)
Code findings were reproduced with scratch tests or Miri; doc findings were
checked against the code. Severity in brackets.
** TODO [medium] Poisson agents' mean period is λ + e^{-λ}, not λ
=src/agent.rs= poisson producer/consumer call =sleep_for(sample)=, and
=sleep_for(0)= acts like =sleep_for(1)= (=src/lib.rs= =SparseSchedule::sleep=
defers even zero-length sleeps). Observed over 20,000 ticks: λ=0.1 gives a
mean period of 1.005, λ=1 gives 1.368. Fix: document the one-tick minimum,
or sample 1 + Poisson(λ-1).
** TODO [low] The "Poisson" producer is not a Poisson arrival process
It draws each gap from Poisson(λ), so gap variance is about λ (observed 60.1
at mean 60.0) rather than the mean² that the M/M/c claims in =src/lib.rs:4-5=
and =README.md= need (about 3,600). Fix: sample exponential or geometric
gaps, or drop the M/M/c and arrival-rate wording.
** TODO [low] Messages sent to a Proactive agent never reach =on_message=
The engine pops the queue only for Reactive agents, so a Proactive target
accumulates messages (1,000 queued, 0 =on_message= calls in the repro) while
they are recorded as delivered. No doc says so, and =examples/CANDIDATES.md=
(Calendar -> Proactive Door) assumes otherwise. Fix: document it and fix
CANDIDATES.md, or deliver queued messages to Proactive agents.
** TODO [low] Writable =AgentContext::name= changes routing in small simulations
=pub name= (and =pub time=) contradict "Routing identities are read-only to
callbacks". With 8 or fewer agents, =agent_id= recognizes the sender by
=ctx.name=, so overwriting it reroutes sends; with 9+ agents it does not.
Fix: make both fields private with getters, or recognize the sender by slot.
** TODO [low] Poisson agents cannot be seeded
They sample =rand::rng()=, so identical simulations differ between runs
(3,247 vs 3,281 produced). This conflicts with deterministic experiments.
Fix: accept a seed or seeded RNG, or document the nondeterminism.
** DONE [low] A panicking =SelectionPolicy= in =tell= loses a proposal
=RandomSearch= =incorporate= removes the pending proposal before calling the
policy and updates counters after. A panic caught by the caller leaves
=asked: 3, told: 2, outstanding: 0, finished: true=, and the lost token
returns =DuplicateToken= if told again. Fix: run the policy before changing
any state.
** DONE [low] A panicking generator in =ask= strands outstanding tokens
=ask= records each proposal and advances =next_token= inside the loop, so a
panic on the third candidate leaves =asked: 2, outstanding: 2= for tokens the
caller never received; the search can never finish. Fix: generate the whole
batch locally, then commit it to the pending window once.
** DONE [low] Initial-queue messages are consumed with =destination: None=
=Message::new= leaves =destination= empty and =Simulation::try_new= keeps
initial-queue entries as given, so a consumed initial message looks
undeliverable. This contradicts =src/message.rs:21= and README's description
of =destination=. Fix: set the owner as destination in =try_new=, or
document the exception.
** TODO [low] A callback panic half-applies the tick, and =run()= replays it
The command buffer is local to =run= and dropped on unwind, but queue pops,
consumed history, and sleeps are committed per visit. After a caught panic
and resume: a message counts as consumed while its reply is lost, and agents
visited before the panic run again at the same time. CHANGELOG ("wake
transitions stay ordered even if a callback panics") and
=callback_panic_does_not_wake_later_agents_early= treat resuming as
supported. Fix: mark the simulation =Failed= and refuse to resume, or keep
the buffer on the simulation with a per-tick visited guard.
** DONE [low] Linear reflection at 0 loses precision
=normalize= in =src/experiment/cross_entropy.rs= reflects via
=rem_euclid(2.0)=, which rounds =2 + value=. Mean 0, std 0.3: a +1 draw gives
0.3, a -1 draw gives 0.30000000000000004; with std 1e-200 the -1 draw becomes
0.0. Fix: reflect =value.abs()= (=r = |v| % 2; if r <= 1 { r } else { 2 - r }=),
which is exact.
** TODO [low] Elite count overshoots when the f64 product rounds up
=elite_count= takes =ceil(n * fraction)= of the rounded product: 100 x 0.07
gives 7.000000000000001, so 8 elites instead of 7 (also 0.14, 0.28, 0.56).
The existing test expects decimal meaning (10 x 0.2 -> 2). Fix: snap products
within a few ulps of an integer before =ceil=, or document the f64 semantics.
** TODO [low] NaN samples and input order change the CEM update
Above 12 samples, =select_nth_unstable_by= leaves elites in input-dependent
order and ties are unbroken. One NaN in front of 16 tied samples moved the
mean from 0.09375 to 0.15625 and changed =best()=; without ties the fitted
mean differs in the last bit in ~9% of random populations. Docs say NaN
scores are "ignored". Fix: break ties with a fixed key (e.g. =total_cmp= on
the point) and sort the selected elites.
** TODO [low] Circular half-turn tie direction depends on libm rounding
=circular_mean= goes through =atan2(sin, cos)=, so whether an exact half-turn
tie moves negative (as =circular_mean_breaks_a_half_turn_tie_toward_the_negative_direction=
pins) depends on trig rounding: 10 of 64 dyadic centers k/64 move positive
natively, and under Miri the pinned test gives 0.25 instead of 0.75. A
refit on one elite also does not reproduce its coordinate exactly. Fix:
average deltas from a reference elite via =circular_delta=.
** DONE [low] A panic payload whose =Drop= panics escapes the runners
=catch_callback= (=core.rs:734=) drops the payload outside =catch_unwind=,
so such a payload unwinds out of =run_parallel= instead of becoming the
documented typed error. Records are still cleaned up; Miri finds no UB.
Fix: forget the payload or drop it inside a second =catch_unwind=.
** DONE [low] =RecordRange::drop= leaks the rest if one record's =Drop= panics
The guard calls =assume_init_drop= per element and stops at the first panic;
Miri reports the later records leaked. Fix: one =ptr::drop_in_place= over the
initialized slice, which keeps dropping after a panic.
** DONE [low] Check the =set_len= invariant instead of assuming it
The SAFETY comment at =core.rs:1096= relies on unchecked facts: =zip= pairs
equal-length lists, rayon runs each shard once, and each shard's trial count
equals its storage length. Fix: =assert_eq!(initialized, storage.len())= in
the disarm loop and cite it in the comment.

** DONE [low] =select_best= is order-dependent for NaN Bernoulli summaries
=BernoulliSummary= fields are =pub=, and =MaximizeBernoulliRate= /
=MaximizeWilsonLowerBound= compare with =partial_cmp(..).unwrap_or(Equal)=.
A NaN rate is "equal" to everything, so the fold is intransitive: rates
(0.9, NaN, 0.5) pick candidate 1 in one order and 2 in another, never the
0.9 candidate. Fix: =total_cmp= with NaN ranked lowest, or private fields
so only =finish()= builds summaries.
** DONE [low] =select_best= keeps whichever duplicate candidate ID came first
Two aggregates with the same =CandidateId= tie on the ID tie-break, so the
result follows input order (attempts 2 vs 4 for swapped inputs). Nothing
rejects duplicates, unlike =SeededRandomSearch=. Fix: document unique IDs,
or reject duplicates.
** DONE [low] =CrossEntropyOptimizer::new= does not report "the first invalid field"
=validate_config= checks =elite_fraction= and =learning_rate= before the
per-dimension fields, then goes dimension by dimension: a NaN mean plus
elite fraction 0 reports =InvalidEliteFraction=. Fix: document the real
order or check in field order.
** DONE [low] =sample_bounded= allocation doc is wrong for empty bounds
The doc bounds allocation by =budget x bounds.len()=, but
=Vec::with_capacity(budget)= reserves outer vectors even when =bounds= is
empty; =budget = usize::MAX / 8= panics with capacity overflow. Fix: state
=budget x (bounds.len() + 1)= with a =# Panics= note, or use =try_reserve=.
